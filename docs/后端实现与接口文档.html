系统定位

本项目是一个美甲AI试戴与智能推荐系统的 Demo 后端，覆盖用户侧（手部分析、AI试戴、款式推荐、智能对话、手部标准化、评测反馈）和运营侧（分类体系管理、款式打标、推送审核、数据报表）两大业务线。

AI 能力由三套模型驱动：Gemini 2.5 Flash（文本生成与 JSON 结构化输出）、Qwen VL Plus（手部图像分析）、gpt-image-1（AI 试戴图片生成）。所有模型均通过 OpenAI-compatible 接口统一调用，便于切换和扩展。

3. 接口文档

3.1 用户侧 — 手部分析与标准化

POST /api/analyze-hand

上传手部图片，调用 VL 模型分析肤色、手型、推荐色系/风格/甲形，返回手部档案。

参数类型必填说明
hand_image_urlstring是手部图片 URL
user_idstring?否用户标识

响应：HandProfileResponse — 包含 hand_profile_id、skin_tone、hand_shape、recommended_colors/styles/nail_shapes、analysis_reason、analysis_mode

GET /api/hand-profile/{hand_profile_id}

根据 hand_profile_id 获取已存储的手部档案。返回 404 如果不存在。

POST /api/standardize-hand

上传手部图片进行标准化质量检查（5项标准），检测是否已有美甲。通过检查后存储为标准手图，后续试戴可复用。

参数类型必填说明
hand_image_urlstring是手部图片 URL
user_idstring?否关联用户，存入 user→hand 映射

响应：StandardizeHandResponse — 包含 quality_pass（5项逐项结果）、nail_art_detected、standardized_hand_id、processing_note

GET /api/user-hand-status?user_id=

查询用户当前选中的标准化手图（向后兼容）。

响应：{has_hand, standardized_hand_id, standardized_image_url}

GET /api/user-hands?user_id=

获取用户全部标准化手图列表，包含每张图的选中状态。前端展示所有已存手图，用户可切换选中、删除或上传更多。

响应：{user_id, hands: [{hand_id, image_url, selected}]}

PUT /api/user-hands/sync

前端离开页面时调用，批量同步用户的完整手图集合及当前选中状态。

参数类型必填说明
user_idstring是用户标识
handsUserHandItem[]是完整手图列表，每个包含 hand_id、image_url、selected；有且仅有一张 selected=true

响应：UserHandsResponse — 返回同步后的完整手图列表

3.2 用户侧 — 款式推荐与对话

POST /api/recommendations

基于用户手部特征和查询文本，多因子打分 + LLM 生成推荐理由，返回推荐款式列表。

参数类型必填说明
querystring?否用户搜索/需求描述
hand_profile_idstring?否手部档案 ID（优先级高）
skin_tonestring?否直接传肤色（fallback）
hand_shapestring?否直接传手型（fallback）
limitint否返回数量（1-20，默认由服务端决定）

响应：RecommendationResponse — 包含 recommendations 数组（每项含 style_id、style_name、image_url、reason、matched_tags、score）

POST /api/chat

智能对话接口，支持多轮对话。结合手部特征和 RAG 检索结果，由 LLM 生成结构化回答。

参数类型必填说明
querystring是用户问题
user_idstring?否用户标识
hand_profile_idstring?否手部档案 ID
conversation_idstring?否会话 ID（不传则新建）

响应：ChatResponse — 包含 conversation_id、answer（scene_analysis + recommendations + tips + follow_up）、suggested_questions、generation_mode

3.3 用户侧 — AI 试戴与图片

POST /api/upload-image

上传图片文件（multipart/form-data），保存到本地 storage 并返回可访问 URL。

参数类型必填说明
fileUploadFile是图片文件

响应：UploadImageResponse — 包含 url、filename、size

POST /api/try-on

AI 试戴：将用户手图与款式图合成，生成试戴效果图。调用 gpt-image-1 images/edits API。

参数类型必填说明
hand_image_urlstring是用户手部图片 URL
style_image_urlstring是美甲款式图片 URL

响应：TryOnResponse — 包含 result_image_url、generation_mode、warnings

POST /api/generate-composite

商家合成图：将裸手模板与款式图合成（与 try-on 使用同一 Prompt）。

参数类型必填说明
style_image_urlstring是款式图 URL
template_image_urlstring是裸手模板 URL

响应：CompositeResponse — 包含 composite_image_url、generation_mode

3.4 用户侧 — 评测与事件

POST /api/evaluations

提交评测打分。

参数类型必填说明

GET /api/evaluations/stats?target_type=

GET /api/evaluations?target_type=&target_id=

记录用户行为事件（曝光、试戴、收藏、点赞、踩、下单）。

GET /api/events?limit=

获取款式级别的事件统计（含试戴率、收藏率、下单率）。

3.5 款式打标

POST /api/extract-tags

对单张款式图进行 VL 标签提取（12 维度 v2 标签体系打标）。值域从数据库动态加载，支持 Gemini → Qwen-VL → mock 三级 fallback。

参数类型必填说明
image_urlstring是美甲款式图片 URL

响应：StyleTagsResponse — 包含 style_id、12 个标签维度字段、candidate_tags、analysis_mode

GET /api/styles/{style_id}/tags

获取已存储的款式标签。

PUT /api/styles/{style_id}/tags

人工修正款式标签（审核后覆盖）。

POST /api/evaluation-dataset/batch-extract-tags?limit=

批量打标入口：对竞赛评测数据集（XLSX）中的全部种子款式进行批量 v2 标签提取。可选 limit 参数控制处理数量。内部遍历每款的 enhanced_style_image_url，调用 VL 模型打标后持久化到 DB。

参数类型必填说明
limitint?否限制处理数量，不传则全量

响应：BatchExtractResponse — 包含 total_styles、updated_styles、failed_styles、analysis_modes（各模型打标数量分布）

POST /api/db/tag-seed-styles?limit=

对数据库中已有的种子款式进行批量 VL 打标（从 styles 表读取，与 batch-extract-tags 不同的是从 DB 而非 XLSX 获取款式列表）。

批量打标 CLI：也可通过命令行触发： 
cd backend
python scripts/batch_tag_extract.py            # 全量处理
python scripts/batch_tag_extract.py --limit 5   # 只处理前 5 张

4.1 Chat 对话 Prompt

System Prompt

你是美团丽人美甲频道的AI推荐顾问。你根据用户的问题和手部特征，从候选款式中挑选合适的款式，
生成结构化、自然、有帮助的回答。如果用户的问题是对上一轮的追问（如「还有吗」「换一批」「其他风格呢」），
应参考历史对话中被推荐过的款式，避免重复推荐。只输出合法JSON，不要输出Markdown。

User Prompt（动态构建）

「动态构建」含义：此 Prompt 并非固定模板，而是在每次请求时由服务端实时填充。填充内容来自三个来源——① RAG 检索出的候选款式列表（从 200 款中按匹配分排序取 Top 8）；② 用户手部特征（从 hand_profile_id 查出的肤色、手型、推荐色系/风格/甲形）；③ 历史对话记录（最近 10 条）。LLM 拿到这些上下文后，从中挑选 3-4 款生成结构化回答。 

历史对话：
- 用户：{上一轮问题}
- 助手：{上一轮分析}（推荐了{款式1、款式2、款式3}）

用户问题：{当前query}
手部特征：肤色{skin_tone}，手型{hand_shape}，推荐色系{colors}，推荐风格{styles}，推荐甲形{nail_shapes}
候选款式列表（只能从下面选）：
- style-001 | 奶油猫眼 | 标签: 猫眼, 奶油白, 显白, 甜美

请输出JSON：
{"scene_analysis":"结合用户问题和手部特征的简短分析，1-2句",
 "recommendations":[{"style_id":"必须从候选列表中选","style_name":"","image_url":"","reason":"结合手部特征的推荐理由"}],
 "tips":"额外搭配建议",
 "follow_up":"一个引导性问题，帮助用户继续探索",
 "suggested_questions":["推荐1-3个用户可能感兴趣的下一个问题"]}
要求：recommendations选3-4款，reason须提及用户的手部特征或问题场景，follow_up要自然不生硬。
如果历史对话中已推荐过某些款式，本轮应优先推荐不同的款式。

4.2 推荐理由 Prompt

使用场景：当用户调用 POST /api/recommendations 时，服务端先通过多因子打分筛选出 Top N 款式，然后将这些款式和用户手部特征一起发给 Gemini 2.5 Flash，由 LLM 为每款式式批量生成一句 15 字以内的个性化推荐理由（如「裸色衬自然肤，纯色法式显高级」），替代原来千篇一律的模板理由。若 LLM 调用失败，则回退到模板理由。

System Prompt

你是美甲推荐顾问。只输出合法JSON，不要输出Markdown。

User Prompt（动态构建）

运行时填充用户手部特征和打分筛选出的候选款式列表，LLM 批量生成个性化推荐理由。 

你是美甲推荐顾问。根据用户的手部特征，为以下N款美甲款式各生成一句简短的推荐理由。

用户手部特征：
- 肤色：{skin_tone}
- 手型：{hand_shape}
- 推荐色系：{colors}
- 推荐风格：{styles}
- 推荐甲形：{nail_shapes}

候选款式：
- {style_id} | {style_name} | 标签: {tags}

请输出JSON：
{"reasons":[{"style_id":"...","reason":"一句话推荐理由，15字以内，自然口语化"}]}

要求：每条理由15字以内，必须结合用户肤色或手型特征，各款理由要有差异化，不要千篇一律。只输出合法JSON。

4.3 手部标准化质检 Prompt

System Prompt

你是一个手部图像质量检测器。只输出合法JSON，不要输出Markdown。

User Prompt

请检查这张手部图片是否满足以下所有条件：
1. 手指朝上，手背平放拍摄
2. 完整露出手部（五指都能看到）
3. 五指微微张开，不并拢
4. 光线明亮均匀
5. 背景干净，无明显杂物

输出JSON格式：
{"quality_pass":true/false,

 "nail_art_detected":true/false}

4.4 手部分析 Prompt

System Prompt

你是美甲推荐顾问。只输出合法 JSON，不要输出 Markdown。
只分析美甲推荐所需的手部视觉特征，不输出身份、健康或敏感判断。
字段名必须使用英文，所有字段值必须使用中文，禁止输出英文标签。

User Prompt

请分析用户手图，输出字段：
skin_tone:string, hand_shape:string, recommended_colors:string[],
recommended_styles:string[], recommended_nail_shapes:string[], analysis_reason:string。

4.5 AI 试戴 Prompt（统一版）

Task Prompt（英文，用于 images/edits API）

You are a professional AI nail try-on image editor.

TASK:
The first image is the user's real hand photo.
The second image is the target nail design reference.

Your task is to completely replace the existing nails in image 1 with the nail design from image 2.

IMPORTANT:
The original nails in image 1 are NOT part of the target design.
They must be treated as temporary placeholder nails only.

STEP 1 — REMOVE ORIGINAL NAIL DESIGN
First, completely ignore and remove the original manicure from image 1.
Restore each fingernail to a clean natural bare nail state:
- remove original color, nail shape influence, nail length influence
- remove original gradients, decorations, gloss style
- remove existing acrylic/gel appearance

The original manicure in image 1 must NOT affect the final result in any way.

STEP 2 — APPLY TARGET DESIGN
Then accurately reconstruct the manicure from image 2 onto the hand in image 1.
Strictly copy from image 2:
- nail shape, nail length, nail thickness, curvature
- color, patterns, decorations, gloss/matte finish
- transparency, texture, placement of every detail

IMPORTANT CONSTRAINTS:
- Do NOT blend the old nails with the new nails
- Do NOT preserve any original nail color or shape
- Do NOT adapt the target design to the old manicure
- Do NOT create a hybrid manicure

HAND PRESERVATION RULE:
Except for the nail area, absolutely nothing else may change.
Preserve exactly: hand pose, finger shape, skin texture, skin tone,
wrinkles, lighting, shadows, reflections, jewelry, camera angle,
depth of field, background, image composition.

Only modify the nail regions.
The final image must look photorealistic and naturally integrated.

4.6 款式标签提取 Prompt

System Prompt

你是美甲款式图结构化打标助手。只输出合法 JSON，不要输出 Markdown。
必须对全部 12 个字段完成打标；数组字段只能从值域中选一个或多个；
枚举字段只能选一个值；无法判断时数组填 []，枚举填 unknown。
禁止自造值域外标签；若确有合适但值域没有的新词，写入 candidate_tags，格式为「字段名: 建议值」。
字段名使用英文，字段值使用中文。

User Prompt（动态构建值域）

请分析这张美甲款式图，输出 JSON，包含以下字段：
- color_system（色系，数组，可多选）: 裸色系, 粉色系, 红色系, 蓝色系, ...
- style_tags（风格标签，数组，可多选）: 法式, 简约, 甜美, ...

- nail_technique（美甲技法，枚举，单选）: 猫眼, 渐变, 镜面, ...
- nail_decoration（装饰，枚举，单选）: 无装饰, 碎钻/小钻, ...
- nail_finish（表面效果，枚举，单选）: 亮面, 磨砂, ...
- nail_shape（甲形，枚举，单选）: 杏仁形, 方圆形, ...
- nail_length（甲长，枚举，单选）: 短甲, 中甲, 长甲
- finger_shape（指形，枚举，单选）: 修长, 标准, 短宽

打标原则：season_tags 若选「四季通用」则不再叠加其他季节；
nail_decoration 若选「无装饰」则不再叠加其他装饰；
skin_tone_suitability 若选「全肤色通用」则不再叠加其他肤色。

5. 核心架构与实现细节

5.1 多模态客户端统一适配

所有 LLM/VLM 调用均通过 multimodal_client.py 中的统一适配层，核心函数：

  • 文本生成：generate_text_json_with_gemini() → 内部调用 _generate_text_json_openai_compatible()，通过 OpenAI-compatible chat/completions 端点 + response_format: json_object 强制 JSON 输出
  • 图片分析：analyze_image_json_with_gemini() / analyze_image_json_with_qwen_vl() → 内部调用 _analyze_image_json_openai_compatible()，消息格式为 [text, image_url] 多模态数组
  • 容错机制：首次调用带 response_format: json_object，若失败则去掉该参数重试；JSON 解析前自动剥离 markdown 代码围栏（```json ... ```）
  • Fallback 链：手部标准化 Gemini → Qwen → 默认通过；手部分析 Qwen → Mock；Chat Gemini → Mock；推荐理由 Gemini → 模板理由

5.2 Chat 多轮对话与 RAG 检索

对话流程：

  1. 关键词提取：将用户 query 与已审批标签值域做交集，提取命中标签作为检索关键词
  2. 款式检索：遍历 200 款候选，按 matched_tags × 12 + query_hits × 6 + hot_score × 0.3 打分排序，取 Top 8
  3. 历史管理：对话历史存储于内存 dict，每轮追加 user+assistant 消息（含推荐款式名），最多保留 10 条，超量自动截断
  4. LLM 生成：将历史、手部特征、候选列表注入 Prompt，要求 LLM 输出结构化 JSON，且避免重复推荐历史中已出现的款式
  5. 响应构建：解析 LLM 返回的 JSON → ChatResponse（含 scene_analysis、recommendations、tips、follow_up、suggested_questions）

5.3 推荐多因子打分

打分公式：

score = matched_tags × 12 + query_hits × 6 + business_score

business_score = hot_score × 0.35 + signal_score × 0.45 + life_cycle_bonus

signal_score = Σ(signal.value × signal.weight)  对每个 signal
  - 试戴收藏率 value 放大 100 倍
  - weight 来自 DB 配置

life_cycle_bonus: 上升期 +8, 峰值期 +5, 观察期 +2, 衰退期 -3

约束构建：从 skin_tone/hand_shape 映射到对应标签值，与 query 中命中的标签合并；若无约束则退化为热门标签 Top 6。

5.4 手部标准化质检

  • 5 项标准：手指朝上平放、完整露出手部、五指微张、光线明亮、背景干净
  • 美甲检测：同时检测是否已有美甲，若有则记录描述但不做去除处理（直接入库）
  • 存储映射：hand_id = "hand-" + SHA1(image_url)[:10]，同时建立 user_id → hand_id 映射
  • 不通过处理：返回 quality_pass=false + 逐项结果 + issues 描述 + 引导文字

5.5 AI 试戴图片生成

  • 统一 Prompt：用户试戴（try-on）和商家合成（composite）共用同一套英文 Prompt，只是输入图片不同
  • 图片尺寸：根据原图宽高比自动选择输出尺寸（1024×1024 / 1024×1536 / 1536×1024），不支持时回退 1024×1024
  • 白边裁剪：生成结果自动裁剪顶部/底部纯白 letterbox 边距（阈值 248，最多裁剪 12% 高度）
  • 兜底方案：当 IMAGE_GENERATION_ENABLED=false 或调用失败时，生成 SVG 预览图（左右并列显示手图+款式图）保证 Demo 可展示
